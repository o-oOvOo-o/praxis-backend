# Cunning3D Gaea Flywheel

Use this skill when the user asks Praxis to inspect, run, debug, or advance a Gaea heightfield node through the Cunning3D flywheel.

## Canonical execution contract

- Treat the plugin's `runtime/c3d_devflywheeltool` directory as the only flywheel business, ledger, and evidence implementation.
- Run commands through `/gaea <command>` in Praxis. For plugin development, use `scripts/c3d-flywheel.ps1 <command>` from this plugin root.
- Never reproduce ledger scoring, parity classification, next-command selection, or artifact promotion in plugin or TUI code.
- Use `probe-bin --bin gaea_<probe> -- <args>` when no first-class flywheel command exists.
- Use the canonical Gaea target directory selected by the wrapper; never create task-specific Cargo target roots.

## Mandatory CCE architecture authority

Read `Cunning3D_1.0/docs/dev/cunning_cce_engine_hosted_only_authority_20260723.zh.md` before changing GPU execution or declaring a node production-ready. It is the final deployment authority. Use `cunning_compute_cda_loom_final_architecture_20260714.zh.md`, especially section 22, only for EngineHosted CCE internals; its global-runtime and direct-WGPU deletion conclusions are historical.

- A GPU algorithm has one handwritten source: canonical WGSL.
- NativeEditorWgpu and host Standalone WGPU remain protected direct WGSL/WGPU production paths. Only EngineHosted projection enters CCE; the flywheel must never gate or replace native cook with Hosted catalog, artifact, planner, or callbacks.
- A normal single-entry GPU node publishes its EngineHosted product through `automatic_compute_implementation`. WGSL ingestion, Naga validation/reflection, Shader Product, Canonical Compute Program, Compute IR, and host artifacts are generated by shared CCE infrastructure. `automatic_compute_implementation_with_projection` is deletion-only debt.
- A real CPU/GPU or multi-stage node must publish through `compose_hybrid_product` and a declarative `HybridProductRecipe`. CPU work remains a typed Rust stage; GPU work references shared canonical programs or automatically ingested WGSL.
- Dynamic HeightField Hybrid publication stores a declarative `HybridProductTemplate`, never a recipe containing one cook's exact extent/stride/layout and never a function callback builder. Resolve schemas only from typed product inputs, another logical value, compiled Compute Program outputs, or a genuinely fixed literal before final `compose_hybrid_product`.
- Require Hybrid publication to exact-cover product input/output slots, Compute stage symbols, and every referenced Program axis. Map them only to NodeCatalog port/parameter keys plus closed projections, resolve real IDs once at Hosted provider freeze, and reject node-name, port-order, default-value, or runtime string inference.
- During Hosted provider freeze, bind every Hybrid publication to one NodeCatalog owner and freeze its real NodePortId/ParamId, exact HeightField CDA pack, parameter contract, and centrally derived binding. Reject any type/binding collision with Automatic or Canonical products; an incomplete Hybrid materializer fails closed and never falls back to RuntimeOp/native cook.
- Publish topology-changing Hybrid choices as one closed immutable variant family under the same NodeCatalog owner. Require exactly one fallback; explicit variants may use only exact predicates over Structural/Specialization parameter keys. Freeze real ParamIds and value kinds, reject overlapping predicates, and put every variant in the offline artifact closure. Prepare selects once; ParamBlock repack never reselects.
- Parameter recipes inside multi-stage products bind Program slots to stable ProductValue identities, not fabricated NodePorts. Compile every Hybrid Compute stage through the shared Program stage compiler that owns Canonical Program instantiation, Compute IR, imports/outputs, output schemas, ProductData, and ParamBlock recipes; never add a second stage packer.
- Freeze Rust-stage execution from the exact Hybrid Product contract set. Product `stage + semantic_hash` references and executor inventory must form an exact closure: reject missing, orphan, duplicate, nil, zero-hash, or semantically drifted registrations. Never construct a default/temporary empty Rust-stage catalog in production FFI.
- Freeze Product→Program→Shader reachability once in `cunning_engine_hosted_cce`; Hosted provider coverage and offline artifact cooking must consume the same closure and reject authority collisions or nodes with no shader entries.
- The generic automatic CPU RustStage exists only to productize representable legacy Geometry `NodeOp` CPU oracles. It rejects hidden `GpuRuntime` access and is not acceptable evidence that a HeightField GPU node has migrated to CCE.
- Static editor descriptors, Rhai nodes, and native plugins do not own execution. Every executable node must resolve through NodeCatalog; dynamic/plugin publication requires an atomic `NodeDefinition + NodeImplementation` revision and `definition: None` is forbidden.
- A node definition is only a semantic publication shell. It must not construct `NodeProductDescriptor`, `NodeProductStageDescriptor`, `NodeComputeProgramRef`, Shader IR, Compute IR, backend objects, or direct WGPU execution.
- Parameter and port projection may be declarative product data, but it must never become a node-specific runtime packer, lowerer, executor, shader emitter, or backend binding table.
- Ordinary single-entry uniforms first use reflected automatic projection from unique NodeDefinition parameter names/types and canonical input metadata. Legacy packed blocks use entry-specific `@cce-uniform` component semantics beside canonical WGSL; build-time Naga validation must prove the exact entry, used binding, member type, and lanes before shared projection consumes them. Never copy a complete node uniform layout or register `ComputeProgramParameterPacker` for the node.
- Automatic Program publication is a closed gate: every reflected ParameterBlock requires one complete validated automatic layout. Missing layout blocks promotion at the catalog boundary and may not be deferred to NodeProduct projection or runtime.
- Ordinary single-entry nodes use build-time validated `@cce-node*` metadata only as a minimal join: entry/type identity, shader-binding-to-port-key mapping, closed required predicates, and explicit uniform-semantic sources. NodeCatalog is the sole authority for display/load identity, typed ports and requiredness, CDA surface/pack, determinism, complete parameter inventory/update class, defaults, publication, and capabilities. The Hosted provider must resolve that owner and fail closed on any drift. Reject duplicated NodeCatalog fields in WGSL metadata, a parallel Rust publication inventory, node-name inference table, packer, lowerer, schedule, or host shader.
- Automatic and shared Canonical Program discovery must remain NodeCatalog-free. The only owner join is the immutable `EngineHostedHeightfieldProductRegistry` freeze, which validates admission, ports, parameters, axes, projections, and Compute contracts once before runtime indexing.
- Product records must not mirror node type, binding, or Compute contract authority. Before freeze derive type from publication and binding from the contract; after freeze derive type only from the NodeCatalog owner.
- Never add a product-local EngineHosted binding string. Automatic and shared Canonical Program bindings are centrally derived from publication kind plus type id.
- Never add a node parameter-to-shader-specialization mapping. Shader Product reflection and Canonical Program dispatch own specialization; structural revision owns relowering.
- Never copy Program shader entries into a Hosted dependency contract. The immutable `ComputeProgramDescriptor` is the sole shader dependency authority.
- Never expose concrete Hosted registry or implementation lookup to production consumers. Only the neutral `RuntimeNodeProductProvider` trait crosses the module boundary, and it must prepare one complete typed NodeProduct atomically.
- After Hosted registry freeze, use NodeCatalog-owned port and parameter IDs directly. Publication keys are joins, never permission to rerun an ID derivation algorithm.
- Compile Canonical Program recipes and Automatic uniform semantics during lowering into the same generic expression/write plan: resolve keys to NodeCatalog-owned `ParamId`, validate reflected uniform coverage and layout once, and emit offset-sorted writes. Initial pack and dynamic repack must share the sole evaluator and must never scan `NodeDefinition`, read publication metadata, match member names, reread reflection, rebuild a string index, or own a second parameter inventory.
- Freeze one immutable parameter contract per Hosted bound product from the NodeCatalog owner. Dynamic repack consumes a borrowed sparse override view with frozen defaults and structural IDs; it must not rescan `NodeDefinition`, reconvert defaults, clone a complete parameter map, or copy that contract into each lowered instance.
- Consume `NodeProductPreparationRequest` by value as the public one-shot preparation input. Pure Compute providers may project it internally to a by-value `ComputeLoweringRequest`; Hosted expansion must borrow a validated default-plus-sparse view and move only persistent input packing into the lowered program. Reject request cloning, `Clone` implementations on either request, and cold-path full parameter materialization.
- Use the neutral `ComputeParameterValueSource` across generic CDA/provider boundaries. EngineHosted graph lowering must borrow a node-scoped ParamSnapshot/compiled-node view and must not clone all `GraphParameterValue`s, rebuild parameter targets per lookup, or materialize an entry parameter map; owned carriers are only for callers that already own values and tests.
- Structural revision must consume the neutral canonical parameter-value digest from `cunning_core::param_table` and combine frozen `ParamId + ParamValueDigest`. Reject Hosted JSON serialization, duplicated value-hash grammars, and temporary encoding allocations.
- Resolve every ParamBlock to one immutable import/byte-size/layout target when the lowered program is created. Canonical and Automatic recipes must both hold this target; dynamic repack and sidecar validation must not traverse Compute IR imports or resource versions and must not clone parameter bytes for self-validation.
- Dynamic repack must update the existing frozen-order ParamBlock slice in place, reuse every fixed-size byte allocation, and refresh only block content plus the sole revision. Reject replacement block vectors, fixed-size buffer churn, repeated target lookup, duplicate revision hashes, and ramp LUT implementations that clone/sort the same ramp once per sample.
- Prepared Region structure caching belongs only to `cunning_engine_hosted_runtime`. Key immutable templates by program revision, instance path, region, host device, and exact boundary schema/packing; keep runtime resources and dynamic bytes in pooled leases. Cache immutable CCE execution plans per backend-profile contract, borrow Logical Plans during verification/planning, and share nested Compute plans with the Runtime; dynamic recook must not rerun Loom/planning or deep-clone plans. Planning uses an admission-neutral envelope while the sole Compute Runtime reservation authority performs exact current-memory admission before submission. Whole-region CDA cache hits must bypass Hosted prepare entirely, dynamic changes must repack pooled blocks, and Structural/input-contract drift must rebuild fail-closed. Reject node caches, generic-CDA CCE caches, Native/Standalone coupling, node-lowering clones, or full-region recomposition during repartition.
- ParamBlock bytes are versioned shared slices. Repack through copy-on-write: overwrite in place when no GPU submission retains the prior version, allocate only when an in-flight submission still owns it, and bind by cloning the shared owner rather than the byte payload. Derive a stable Host ABI identity from graph revision, instance path, region, node, import, and layout, carry revision separately, and require the host Compute Domain to cache read-only native buffers by device/physical contract/identity/revision. Same-revision execution must perform no native allocation, upload, or prepare-time payload copy; completion must retain old in-flight revisions. Reject immutable-ProductData misclassification and node/host-specific upload caches.
- Cache immutable Host ABI plan wire templates in a bounded EngineHosted backend cache keyed by plan, target-profile, target-identity, and resolved-artifact identity. Reuse allocation, in-place, binding, access, dispatch, command, and output arrays; submissions may change only resource descriptors for current resource views and versioned ParamBlock identity/revision/pointers. Reject cached dynamic tokens, admission state, prepared handles, or reservations.
- Require each host Compute Domain to cache a validated immutable physical-plan skeleton only behind an exact normalized resource/dispatch contract. Artifact resolution, target binding, physical requirements, ownership/timeline proof, and detached command/dispatch/output data are reusable; resource tokens, ParamBlock versions/payloads, claims, bridges, physical memory facts, prepared handles, admission, and reservations are submission-local. Require development hit/miss diagnostics before claiming steady-state reuse.
- Install recipes only through checked exact target coverage and retain deterministic frozen-target order. Repack must emit that order directly and must not rebuild target sets, repeat target lookup, or hash each new block a second time merely to validate its own output.
- `@cce-node-require` may target only Structural NodeCatalog parameters. Applicability is checked before lowering; repack never switches products.
- Interactive command-stream algorithms must normalize effective tools, target-layer semantics, clamp policy, and stamps once in shared geometry substrate before compiling versioned semantic commands into shared typed schedules and Canonical Compute Programs. Dynamic target layers may only expand declarative shared program/upsert fragments; pointwise batches and ordered stencil ping-pong remain resident. Node JSON below semantic preparation, editor/cache state, NodeId, raw WGPU, host APIs, node-specific Shader/Compute IR, packers, and node-owned dispatch loops are architectural blockers.
- Product topology expansion is legal only inside NodeCatalog graph compilation. Its closed contract must list every Structural parameter and input-presence dependency; graph compilation materializes and validates one ordinary static NodeProduct before CDA/Loom. Reject runtime expander registries, undeclared topology dependencies, product-id drift, or any expander visible to Compute IR/backends. Prepared data uses a stable contract while layer/instance identity stays in output semantic.
- An automatic dispatch domain must be unique or declared through build-time validated `@cce-domain|entry|binding` beside canonical WGSL. Reflected binding order and node-local selection are forbidden.
- If an ordinary single-entry WGSL entry supports only exact closed structural values, declare build-time validated `@cce-require-axis` metadata beside that entry. Automatic CCE owns the typed axis, semantic revision, and fail-closed check. Never preserve a hand-written single-dispatch Program merely to reject unsupported modes, and never let automatic publication silently ignore a structural node parameter.
- Genuine multi-dispatch parameter variation belongs to the canonical program's closed `ComputeProgramParameterRecipe`. Use `UniformMembers` for reflected blocks and typed payload variants such as `RampLutF32` for non-uniform buffers. Automatic and Hybrid composition both lower through `infer_automatic_parameter_blocks`; the generic runtime evaluator remains the sole byte authority.
- Require canonical node definitions to contain zero `NodeComputeParameterWordExpr` and zero `NodeComputeParameterBlockProjection`. Semantic axis/input/output/publication overrides remain legal; member formulas, Ramp payloads, parameter arenas, debt manifests, and node exceptions do not.
- Do not add per-node Loom lowerers, runtime packages, planner allowlists, direct WGPU schedules, Unity/Unreal shader copies, or node-specific CCE executors. Loom is the shared CCE optimizer over typed products, not another node runtime.
- Render HLSL and Render IR are outside this flywheel and outside CCE node compute.
- Run `/gaea architecture-guard --node <Node> --json --strict` before promotion. A blocker is architectural failure even when parity passes.
- Require both `no_node_specific_runtime_projection_authority` and `no_runtime_parameter_packer_framework` to pass. The second check is repository-global and naming-independent: while any callback packer framework or registration exists, no new Gaea node may be promoted, even if its own name never appears in that code.
- Require `closed_world_node_gpu_authority` to reject hand-built Hosted Product/Shader IR/Compute IR/program authority in canonical node definitions. `cce_product_authority` must look for formal WGSL/Canonical/Hybrid publication outside NodeDefinition; it must never require `compose_hybrid_product` or automatic implementation code inside the node definition. Neither check may classify protected NativeEditorWgpu or Standalone WGPU scheduling as CCE debt.
- A new native node may add the direct WGPU schedule required by the shared canonical WGSL algorithm. It must also publish the same WGSL/schedule semantics to EngineHosted through automatic publication or a shared algorithm-level recipe; never force native execution through CCE to satisfy a debt counter.
- Run `Cunning3D_1.0/ci/check-cce-authority.ps1` as the repository-wide companion gate. The node guard rejects node-local authority; the repository gate rejects a new parallel authority hidden in shared substrate or runtime code.
- Treat ledger `evidence_summary`, `rust_implementation`, and old artifact terminology as algorithm/parity history only. Never copy an execution architecture from a ledger entry. The top-level `architecture_authority` and the live Rust architecture report supersede every entry.
- If a new node cannot pass the automatic/declarative path, stop and improve shared CCE authoring, ingestion, product composition, or planning. Do not record a node-local workaround as progress.
- Own automatic/canonical Hosted product discovery, parameter-recipe evaluation, lowering verification, and the concrete HeightField provider only in `cunning_engine_hosted_runtime::product_provider`. Generic `cunning_cda_runtime` may contain only the typed NodeProduct protocol, neutral provider trait, and RuntimeValue/GPU-binding projection; it must not restore a `compute_lowerer` module or depend on `cunning_compute_compiler`.
- Own host resource import/export, CCE backend identity, lease retention, EngineHosted output materialization, and immutable ProductData resolution only in `cunning_engine_hosted_runtime::runtime_materialization`. Native WGSL modules must not register Hosted ProductData or callbacks into generic CDA.
- Project Native `GpuField` layout once into protocol-owned `DenseF32FieldPacking` at the generic CDA boundary. EngineHosted providers, recipes, region composition, flywheel fixtures, and generated publications must never reference `kernel_ir::HeightFieldDenseF32Layout` or `kernel_ir::HeightFieldLayerBinding`.
- Publish output layer meaning as protocol-owned `ComputeFieldLayerSemantic`. Only `cunning_engine_hosted_runtime::runtime_materialization` may exhaustively convert it to runtime `GpuFieldLayerSemantic`; generated product/recipe code must never store the runtime enum.
- Do not update a debt manifest, allowlist, scanner exception, or ledger status to legalize a new fork. Promotion evidence must come from the live automatic/declarative product and strict guard.
- If automatic CCE adoption requires changing algorithm math or buffer layout, close parity bottom-up against the frozen oracle: scalar/substrate, every intermediate GPU buffer, final program output, NodeProduct publication, and demanded graph output must be 100% buffer-consistent before promotion.
- Source/generator nodes must use schema-domain automatic ingestion plus the shared HeightField Art source product when applicable. Derived uniforms belong to the typed WGSL semantic-expression grammar, and changed Field channel counts belong to validated `@cce-output-channels`; reject node-local packers, output-schema builders, commit schedules, and family-specific IR.

## Workflow

1. Run `ledger-hygiene --json --strict` before ledger or graph edits.
2. Inspect `status --node <Node> --json`, `open-frontier --node <Node> --all --json`, and `reverse --node <Node> --json`.
3. Run the strict CCE architecture guard before implementation and classify every finding as shared-infrastructure work or algorithm/parity work.
4. Establish the smallest fresh Bridge-vs-Native failing case and localize the first mismatching stage or scalar.
5. Fix shared Rust/WGSL substrate before recipe-specific symptoms when evidence shows a reusable contract gap.
6. Publish only through automatic WGSL ingestion or a declarative Hybrid Product, then rerun the strict architecture guard and remove every reported parallel authority.
7. Require the report's `no_node_specific_runtime_projection_authority` and `no_runtime_parameter_packer_framework` checks to pass. Any node-owned parameter expression or block payload, node-named parameter packer, `pack_<node>_parameters`, callback packer registry, lowerer, recipe builder, binding table, executor, or backend is a blocker, not migration scaffolding.
8. Require `closed_world_node_gpu_authority` to pass for Hosted authority. If the node exposes a missing GPU semantic, improve shared automatic ingestion, reflection, projection, PreparedUpload, or canonical multi-dispatch composition; preserve the legitimate direct-WGPU execution path and never add hand-built Hosted IR to the node.
9. Run the focused exact gate. Do not expand to heavy matrices unless requested or needed for promotion.
10. Perform the mandatory writeback below for both success and useful failure.
11. Run the observability gate below before reporting completion.

## Mandatory writeback

- Treat artifact generation without ledger writeback as incomplete work.
- Update the plugin-owned `runtime/c3d_devflywheeltool/ledger/gaea_operator_ledger.json`; never create a side ledger.
- For every affected contract entry, update `status`, `native_evidence`, `rust_implementation`, `evidence_summary`, and `open_risk` from fresh evidence.
- Use `audited_closed` only for the documented full exact contract. Use `focused_closed` only for explicitly bounded focused closure. Otherwise keep the entry open and record the exact remaining mismatch, rejected hypothesis, artifact path, and next focused command.
- Write back useful failed attempts too. A disproved formula, localized first mismatch, or newly isolated blocker is flywheel memory and must prevent the next agent from repeating the work.
- Update `gaea_flywheel_graph.json` when operator dependencies, blockers, or node relationships change. Update the acceptance matrix when the promotion contract changes.
- Never claim completion from code, screenshots, chat notes, or an artifact directory alone.

## Observability gate

Run all applicable commands after writeback:

```text
/gaea ledger-hygiene --json --strict
/gaea status --node <Node> --json
./ci/check-cce-authority.ps1
/gaea architecture-guard --node <Node> --json --strict
/gaea verify --node <Node> --json --strict
/gaea praxis-panel --node <Node> --json
```

- Confirm `/gaeawheel` shows the new progress/status and blocker summary from the same canonical ledger.
- If meaningful work occurred but the ledger-backed panel did not change, the flywheel turn is not complete.
- Report the before/after ledger status, fresh artifact path, remaining blocker, and the `/gaea` command that reproduces the next step.

## Praxis commands

- `/gaeawheel` renders the canonical CLI-owned flywheel panel.
- `/gaea <command> <args>` invokes the plugin-owned real flywheel CLI.

Do not claim a node is closed unless strict raw parity, required branch coverage, ledger contract status, the strict CCE architecture guard, `/gaeawheel` projection, and applicable performance gates all agree.
